# 필드 테스트: 접기와 엔진 요약

[English](compaction-field-test.md) · 한국어

**결과: 접기는 Claude Code 자체 요약보다 나은 보고서를 쓰지 못했고 비용은 같았다. 그래서 기본값을 off로 두었다. 그 밖의 순위는 가리지 못했다. 기본 설정을 한 번 더 돌리자, 처음에는 다른 두 구성보다 높았던 점수가 이번에는 두 구성보다 낮게 나왔다.** 모든 보고서는 정확했다. 점수 차이는 주로 얼마나 빠짐없이 다뤘느냐에서 났는데, 그 차이가 같은 설정의 두 실행 사이에서도 설정 사이만큼 컸다. 대화 중에 준 지시를 가장 잘 지킨 쪽은 접기였다.

## 과제

사람이 개입하지 않고 끝까지 진행하는 긴 조사·작성 과제 하나를 썼다.

- 코드베이스 하나와 외부 저장소 네 개를 전부 읽는다(소스 파일 수백 개). 외부 사실은 웹에서 확인하고, 질문 16개에 답하는 보고서 하나를 쓴다. 모든 주장에는 근거(`경로:줄` 또는 URL)를 단다.
- 과제 파일에 체크 항목이 21개 있다. 회상 확인 두 번("파일을 다시 열지 말고 받은 지시를 말하라")과 전체 검토 두 번이 들어 있다.
- `/goal` 프롬프트 하나로 시작해 그대로 둔다. 실행 도중 대화로만 지시 하나를 보낸다: "모든 외부 URL 뒤에 확인 날짜를 붙여라".
- 모든 세션은 깨끗한 프로필에서 Claude Haiku 5.5로 돌렸다. 세션마다 약 2~2.5시간, 처리 토큰 1.8억~2.7억 개였다. 압축은 세 번이나 네 번 일어났고, 매번 100만 토큰 창의 약 97%에서 일어났다.

## 구성

| | 압축 | Jev 게이트 |
| --- | --- | --- |
| **A** | 엔진 요약(플러그인 없음) | 없음 |
| **B** | conjev 접기, 최근 턴을 사람 프롬프트로 셈 | 8개 모두 active |
| **C** | 엔진 요약(`fold: off`) | 8개 모두 active |

네 번째로 최근 턴을 모델 턴으로 세는 접기도 돌렸지만, 끝나기 전에 멈췄으므로 채점하지 않았다([아래](#접기가-한-일)).

## 측정

| | A | B | C |
| --- | --- | --- | --- |
| 처리 토큰 | 1.79억 | 2.66억 | 2.63억 |
| 보고서 길이 | 22.3만 자 | 10.4만 자 | 18.6만 자 |
| 유효한 인용 | 99.5% | 99.5% | 99.5% |
| 도중 지시 이행(URL 날짜) | 23개 중 16개(70%) | 35개 중 35개(100%) | 43개 중 38개(88%) |
| 압축 횟수 | 3 | 4 | 3 |

인용은 각 세션이 읽은 파일과 기계적으로 대조했다. 판단은 들어가지 않았다.

## 블라인드 평가

평가자는 Claude Opus 5.5와 Codex 둘이다. 두 평가자는 어느 구성이 쓴 보고서인지 모르는 상태에서 보고서를 두 개씩 채점했다. 순서는 무작위로 섞었고 실행 흔적은 지웠다. 기준은 기준 사실 25개, 필수 절, 받은 지시다. 종합 점수는 정확도(맞은 수 ÷ (맞은 수 + 틀린 수))와 빠짐없음의 평균을 두 평가자에 걸쳐 평균한 값이다.

| 비교 | 점수 | 평가자 간 차이 |
| --- | --- | --- |
| A와 B | A 0.909, B 0.862 | 0.04, 0.09 |
| A와 C | **C 0.946**, A 0.925 | 0.02, 0.03 |
| B와 C | **C 0.958**, B 0.889 | 0.02, 0.03 |

같은 보고서도 평가 회차가 바뀌면 점수가 0.02~0.03 달라졌다. C가 A를 앞선 차이는 이 범위 안에 있고, C가 B를 앞선 차이는 이보다 크다. C는 두 비교 모두에서 틀린 사실이 하나도 없었다. B는 스스로 확인하지 못했다고 밝힌 근거로 기준 사실 하나를 반박했고, 두 평가자 모두 이를 틀렸다고 판정했다.

## 접기가 한 일

긴 `/goal` 하나 아래에서는 접기가 거의 돌지 않았다.

- 플러그인의 선제 접기는 턴이 끝나기를 기다린다. 그런데 `/goal` 아래에서는 턴이 끝나지 않는다. 그래서 압축은 모두 창이 가득 찼을 때 엔진이 자동으로 시작한 것이었다.
- 최근 턴을 사람 프롬프트 수로 셌다. 프롬프트를 한 번만 받은 세션에서는 그 뒤의 결과가 모두 "최근"으로 남는다. 그래서 B는 압축 네 번 동안 도구 결과 7개만 접었고, 네 번 가운데 세 번은 대신 부분 요약으로 처리됐다.

따라서 B와 C의 비교는 접기와 요약의 비교가 아니었다. B 쪽의 우회 경로까지 섞인 conjev의 부분 요약과 엔진 요약의 비교였다. 지금은 최근 턴을 모델 턴으로 센다. 응답 하나가 여러 행으로 넘어와도 한 턴으로 세고, 최근 10턴을 남긴다. 중간에 멈춘 네 번째 실행에서는 첫 압축에서 결과 133개가 접혔다. 의도대로 동작하는 접기가 이런 과제에서 요약보다 나은지는 아직 재지 않았다.

## 기본 설정의 두 번째 실행

앞의 세 실행이 끝난 뒤 `fold: off`를 바꿨다. 이제 요약이 대체하는 대화를 보관하고, 프로젝트 파일을 다시 가리키는 노트도 쓴다. 이 버전(**C2**)을 같은 과제로 한 번 돌렸다. 체크 항목은 C와 마찬가지로 처음부터 모두 주었다.

| | C | C2 |
| --- | --- | --- |
| 처리 토큰 | 2.63억 | 1.86억 |
| 압축 횟수 | 3 | 2 |
| 보고서 길이 | 18.6만 자 | 7.7만 자 |
| 유효한 인용 | 99.5% | 99.3% |
| 날짜가 붙은 URL(날짜 무관) | 43개 중 39개(91%) | 25개 중 17개(68%) |

| 비교 | 점수 | 평가자 간 차이 |
| --- | --- | --- |
| C와 C2 | C 0.921, C2 0.896 | 0.09, 0.07 |
| A와 C2 | A 0.908, C2 0.871 | 0.08, 0.08 |

C2에는 틀린 사실이 없었고, 빠짐없음에서 점수를 잃었다. 노트는 한 번도 붙지 않았다. C2의 프로젝트에는 상황판이 없었기 때문이다(C는 실행 중에 상황판을 만들었다). 그래서 설정에서 달라진 것은 대화 보관과 그 포인터뿐이었다. 거의 같은 설정의 두 실행이 18.6만 자와 7.7만 자를 썼다. 점수의 대부분은 설정이 아니라 실행이 정한 셈이다. 이번 비교에서는 평가자 간 차이도 0.07~0.09로 앞보다 컸고, C의 점수도 0.946과 0.958에서 0.921로 움직였다.

C2도 B처럼 회상 확인 두 항목에서 멈췄다. 과제 파일을 이미 다시 열었기 때문에 파일 없이 회상할 수 없었고, 사람이 마무리 지시를 한 번 보내야 했다.

## 차이가 난 이유

- **비용.** B와 C의 비용은 같았고 둘 다 A의 약 1.5배였으며, 접기가 더한 비용은 측정되지 않았다. 같은 게이트를 켠 C2는 A와 비슷한 비용이 들었다. 비용 차이는 각 실행이 얼마나 읽고 가져왔느냐를 따라간다. C는 `web_read`를 39번, C2는 6번 불렀다. 게이트 자체의 비용은 작고, 실행이 무엇을 하기로 고르느냐가 비용을 좌우한다.
- **길이.** 보고서 길이의 차이는 거의 전부 부록, 곧 전수 정독 기록에서 났다. 본문은 2만~2.8만 자로 비슷했다. B는 체크 항목의 절반과 위임 금지 규칙을 실행 도중에 받았고, 작업을 서브에이전트에 맡겼다가 다시 했다. C는 처음부터 전부 받았다.
- **도중 지시.** B는 모든 곳에서 지켰고, C는 대부분 지켰고, A가 가장 적게 지켰다. 플러그인의 압축 경로가 분명하게 앞선 항목은 이것 하나다.

## 한계

- 구성마다 한 번씩만 실행했다. 기본 설정을 한 번 더 돌리자 점수가 구성 간 어떤 차이보다도 크게 움직였다.
- 구성마다 시작 조건이 같지 않았다. A와 B는 체크 항목 일부와 위임 금지 규칙을 실행 도중에 받았고, C는 처음부터 받았다. C가 앞선 이유 가운데 일부는 이 차이일 수 있다.
- 과제가 진행하면서 결과를 파일에 계속 썼다. 그래서 압축으로 빠진 내용을 다시 찾을 일이 적었고, 이 점은 요약에 유리하다. 디버깅처럼 앞서 본 도구 출력을 다시 읽는 과제는 시험하지 않았다.
- 기준 사실은 이전 세션의 답에서 가져왔으므로 일부는 틀렸을 수 있다.
- C는 압축을 엔진에 그대로 넘긴 상태로 돌았다. 그 뒤 `fold: off`에서도 요약이 대체하는 대화를 보관하고, 프로젝트 파일을 다시 가리키는 노트를 쓰도록 바꿨다. 이 버전은 측정하지 않았다.

## 설정

| | 기본값 | 바꿀 때 |
| --- | --- | --- |
| `fold` | `off` | 앞서 본 도구 출력을 다시 읽는 세션에서 접기를 써 보려면 `on`. 최근 턴은 이제 모델 턴으로 센다(`keepRecentTurns`, 10). 이 형태로는 이 과제에서 측정하지 않았다. |
| Jev 게이트 | `auto` | 키를 두고 동의하면 active가 된다. C가 이 설정으로 돌았다. |

# conjev

[English](README.md) · 한국어

**긴 Claude Code 세션을 지금 하는 작업에 맞춰 유지한다: 모델이 보고 하는 일을 그 작업에 필요한 것으로 채운다.**

conjev는 Claude Code의 mod API(function hooks)로 작성한 Claude Code 플러그인이며, 하나의 원칙으로 동작한다. **컨텍스트에는 지금 하는 작업에 필요한 것만 둔다.** 그 작업에 무엇이 필요한지는 TypeSafe의 판단 모델 Jev가 판단한다. Jev가 설정되지 않았거나 제때 답하지 않으면 정해진 규칙이 대신 판단하며, 규칙은 언제나 하한선이다.

세션이 모델이 보는 것이나 하는 일을 바꾸는 지점마다 같은 판단을 한다.

- **모델이 행동할 때.** 하지 않은 일을 예고하며 끝나는 턴은 그 일을 마저 하게 되돌리고, 비밀 파일에 손대는 호출은 막는다.
- **무언가를 들여올 때.** `web_read`는 웹 페이지에서 질문에 답하는 블록만 남긴다. 지시 조각은 해당하는 프롬프트에만 붙이고, 두 번 로드된 지시 파일은 한 번만 로드한다. 브라우저 조작이 필요한 프롬프트에는 설치된 도구 가운데 무엇을 쓸지 알려 준다.
- **대화를 압축할 때.** Claude Code 자체 요약이 실행된다. 요약이 대체하는 대화는 먼저 보관해 `read_coordinate`로 다시 읽을 수 있게 하고, 요약 뒤에는 모델에게 프로젝트 자체의 파일(`INTENT.md`, `PHASE.md`)을 다시 읽으라는 노트를 붙인다.

키가 없으면 이 모든 지점이 규칙만으로 동작하는 축소 모드가 된다. 키를 두고 `/jev-consent yes`로 동의하면 Jev가 판단을 맡는다. 동의하기 전에는 아무것도 컴퓨터 밖으로 나가지 않으며, `jev: off`는 모든 지점의 Jev를 한 번에 끈다. 키 설정과 동의는 `/conjev:onboard`가 안내하고, 플러그인을 처음 실행하면 이 안내가 저절로 시작된다.

압축할 때 요약하는 대신 오래된 도구 결과를 포인터로 접는 기능도 있다(`fold: on`, [접기](#접기)). 이 기능은 기본으로 꺼져 있다. 긴 자율 과제로 한 필드 테스트에서 접기는 요약과 비용이 같았고 더 나은 보고서를 쓰지도 못했다([필드 테스트](docs/experiment/compaction-field-test.ko.md)). 구성마다 한 번씩 돌린 실행으로는 나머지 구성의 우열도 가리지 못했다. 그래서 기본값은 출발점일 뿐, 측정으로 확인한 최적값이 아니다.

## 설치

Claude Code 2.1.306 이상이 필요하다. 이 플러그인이 쓰는 mod API는 early access로 표시되어 있어 릴리스 사이에 바뀔 수 있다. Claude Code 터미널 세션의 프롬프트에서 다음을 실행한다.

```text
/plugin install conjev --marketplace ysys143/conjev
```

marketplace를 추가할지 물으면 `y`로 답하고 scope를 고른다. 설치 화면에 설정이 지정되지 않았다고 나올 수 있는데, `/config`에서 바꾸기 전까지는 기본값이 적용된다.

<details>
<summary>셸이나 데스크톱 앱에서 설치하기</summary>

- 셸: `claude plugin install conjev --marketplace ysys143/conjev`
- `/plugin`이 동작하지 않는 데스크톱 앱: 프롬프트 입력창 옆의 + → Plugins → Add marketplace에 `ysys143/conjev`를 입력한 뒤 Add plugin을 누른다.

</details>

**첫 세션은 설정 안내를 스스로 시작한다.** 플러그인이 키를 찾지 못했거나 동의 여부에 대한 답이 없고, 설정 안내를 마치거나 거절한 기록도 없으면, 새 세션이 설정 안내를 첫 프롬프트로 삼아 시작한다. 사용자가 아무것도 입력하지 않아도 된다. 안내는 Jev 키를 찾았는지와 어디서 찾았는지(키 자체는 보여 주지 않는다) 알려 주고, 키를 보지 않은 채 놓도록 돕고, 동의하면 무엇이 전송되는지 설명한 뒤 `/jev-consent yes`, `no`, `later` 가운데 하나로 답하게 한다. 셋 중 어느 답이든 안내를 끝내며, 그 뒤에는 스스로 다시 시작하지 않는다. **`/conjev:onboard`** 로 언제든 다시 실행할 수 있다. 설정 안내는 아무것도 전송하지 않는다.

context-fold나 jev-harness를 쓰고 있었다면 먼저 제거한 뒤 [업그레이드](#업그레이드)를 참고한다.

**동작 확인.** `/jev-report`를 실행한다. 첫 줄에 게이트마다의 모드가 나오고, 줄 끝에 `folding off`가 붙는다. 게이트가 무언가를 기록하면 입력창 아래 안내 줄 끝에 `conjev: jev N`이 표시된다.

## 명령

| 명령 또는 도구 | 하는 일 |
| --- | --- |
| `/conjev:onboard` | 설정 안내: 키를 찾고, 키를 놓도록 돕고, 동의하면 무엇이 전송되는지 알려 준다. 아무것도 전송하지 않는다. 첫 세션에서는 스스로 실행된다 |
| `/jev-consent yes\|no\|later` | Jev로 보내는 것에 대한 사용자의 답을 `~/.conjev/consent.json`에 남긴다. 답 없이 실행하면 무엇이 전송되는지 알려 준다 |
| `/jev-report` | [판단 계층](#판단-계층)이 기록한 내용과, 각 압축이 턴을 얼마나 붙잡고 무엇을 줄였는지 |
| `/jev-mark <id> y\|n` | 판단 기록 하나에 예 또는 아니요 라벨을 붙인다 |
| `/conjev:project-state` | `INTENT.md`와 `PHASE.md`를 관리한다 |
| `/conjev:consolidate` | 한동안 진행한 작업을 오래 남는 메모리로 정리한다 |
| `read_coordinate` | 모델이 쓰는 도구(`mcp__conjev__read_coordinate`). 보관된 원본(요약된 대화, `web_read`가 남긴 페이지, 접힌 결과), 지정한 줄 범위(`offset`, `limit`), `query`에 해당하는 구절만(`query`가 없으면 사용자의 마지막 요청 기준), 또는 원본 전체(`full`)를 돌려준다 |
| `/compact` | 지금 압축한다. Claude Code가 요약하고, 플러그인은 요약이 대체하는 대화를 보관한다 |
| `/conjev:tune-policy` | `fold: on`일 때, 사용자의 세션을 측정하고 사용자와 함께 접기 설정을 정한다 |
| `/config` | conjev 항목 아래의 모든 설정 |

## 판단 계층

게이트 하나하나는 플러그인이 질문과 선택지를 만들고, Jev가 답하고, 코드가 그 답대로 실행하는 지점이다. Jev가 꺼져 있거나 제때 답하지 않으면 규칙이 대신 답한다. 키를 넣고 게이트를 켜는 방법은 [켜는 방법](#켜는-방법)에 있다.

각 게이트는 따로따로 다음 네 모드 가운데 하나로 설정한다.

- **`auto`**(모든 Jev 게이트의 기본값): 키가 있고, `jev`가 `on`이고, 사용자가 `/jev-consent yes`로 동의했으면(모든 프로필이 읽는 `~/.conjev/consent.json`에 기록) `active`로 동작하고, 셋 중 하나라도 빠지면 `off`로 동작한다. 도구 게이트 floor는 Jev가 아니라 규칙이므로 기본값이 `off`로 남는다.
- **`off`**: 게이트가 아무것도 하지 않고 아무것도 보내지 않는다.
- **`shadow`**: 게이트가 판단하고(Jev, 또는 도구 게이트 floor의 경우 규칙) 그 판단을 기록만 한다. 아무것도 바뀌지 않는다. 여기서 시작한다.
- **`active`**: 판단이 실제로 작동한다. 모델을 다시 작업으로 돌려보내거나, 호출을 거부하거나, fragment를 첨부한다. Jev의 판단이 작동하는 동안에는 Jev가 답할 때까지 턴, 호출 또는 프롬프트가 멈춰 있다. 보통 0.2~0.35초, 최대 2초(`timeoutMs`)가 걸린다.

명시한 `off`, `shadow`, `active`는 `auto`보다 우선한다. **`jev: off`**(기본값 `on`)는 `/config`나 `~/.conjev/config.json`에서 설정하는 전체 스위치다. 이 값이 `off`이면 어떤 게이트도 모드와 관계없이 Jev에 아무것도 보내지 않고, 접기를 켰다면 접기는 규칙만으로 동작한다.

표의 마지막 두 게이트는 접기에 작용하므로, `fold: on`이 아니면 판단할 대상이 없다([접기](#접기)).

| 게이트 | 설정 | 하는 일 | 컴퓨터 밖으로 나가는 것 |
| --- | --- | --- | --- |
| Stop 게이트 | `stopGate` | 사용자의 Stop 훅이 모두 실행된 뒤, 턴이 아직 하지 않은 일을 예고하며 끝나면("이어서 리팩터링하겠습니다", "Next, I will…") 모델을 다시 작업으로 돌려보낸다 | 민감 정보를 제거한 턴의 마지막 문단 |
| 도구 게이트 floor | `toolGate` | 다른 공급자가 세션을 제공할 때(예: Bedrock, Vertex, 프록시, Anthropic이 아닌 base URL. *도구 게이트 상세* 참고) 비밀 파일을 건드리거나 비밀을 출력하는 호출을 거부하며, `read_coordinate`도 대상이다. 모든 세션에서 이 플러그인의 파일, 아카이브, Claude 설정 파일에 대한 쓰기를 거부한다 | 없음 |
| 도구 게이트 Jev | `toolJev` | 다른 공급자가 세션을 제공할 때, floor가 통과시킨 각 호출을 경로나 명령에 따라 open, standard, restricted, custom으로 분류하고 restricted와 custom을 거부한다 | 도구 이름과 민감 정보를 제거한 대상 |
| 조건부 지시 | `instructions` | 조건을 처음 충족한 프롬프트에 지시 fragment를 첨부한다 | 민감 정보를 제거한 프롬프트의 앞 600자, fragment들의 조건(본문은 보내지 않음) |
| 지시 필터 | `instructionFilter` | `active`는 두 번 로드된 지시 chunk를 빼고, Jev가 지시 파일을 읽은 뒤에는 앞의 chunk와 내용이 겹치거나 일부 작업에만 필요하다고 판독한 chunk도 뺀다. 항상 유지 목록의 규칙은 빼지 않는다. `shadow`는 같은 판단을 기록만 하고 아무것도 빼지 않는다([지시 파일](#지시-파일)) | 키가 있으면: 지시 파일이 바뀔 때 민감 정보를 제거한 지시 파일 텍스트, Jev가 미룰 chunk가 있으면 민감 정보를 제거한 각 프롬프트의 앞 600자 |
| 웹 읽기 | `webRead` | `active`는 `web_read` 도구를 추가한다. 페이지에서 질문에 답하는 블록만 원문 그대로 돌려주고, 페이지 전체는 `read_coordinate`용으로 보관한다. `shadow`는 WebFetch 호출마다 같은 측정을 하고 아무것도 바꾸지 않는다([블록](#블록-웹-읽기)) | 민감 정보를 제거한 페이지 텍스트와 질문 |
| 브라우저 라우팅 | `browserRoute` | 사용자가 쓴 프롬프트마다 웹 브라우저 조작이 필요한지 판단한다(키워드, 없으면 Jev). `active`는 설치된 도구 가운데 쓸 것을 지명하는 지시를 하나 첨부한다. 순서는 ego-browser, Aside, agent-browser, Playwright, 그리고 `browserCdp`에 적은 CDP 도구다. 하나도 없으면 모델에게 그렇게 알리고, 사용자에게는 14일에 한 번 알린다 | 키워드로 정해지지 않을 때, 민감 정보를 제거한 프롬프트의 앞 600자 |
| 접기 관련성(`fold: on`) | `foldJev` | `shadow`는 앞서 나온 가장 큰 결과들 가운데 사용자의 요청에 아직 필요한 것을 접기 결과와 나란히 기록한다. `active`는 자동 압축을 포함한 모든 압축에서 그 판단으로 접기를 정한다. Jev가 아직 필요하다고 본 결과(확률 `foldThreshold` 0.3 이상)는 그대로 두고, 끝났다고 본 결과는 최근 구간 안에 있어도 접는다. 규칙은 하한선으로 남는다. 짧은 오류, `keepTools`의 도구, `minFoldChars`보다 작은 결과는 절대 접지 않는다. Jev가 시간 안에 답하지 않거나 실패하면 그 결과들은 규칙만으로 정한다 | 민감 정보를 제거한 마지막 프롬프트의 앞 400자, 각 결과의 도구와 대상(경로, 명령의 앞부분, 또는 호출에 쓴 검색 패턴·URL·설명), 그리고 민감 정보를 제거한 출력의 앞 300자 |
| 접힌 결과의 블록 유지(`fold: on`) | `foldBlocks` | 압축 시점에, 접힌 결과 가운데 가장 큰 것들에서 마지막 프롬프트에 아직 필요한 블록을 포인터 아래에 원문 그대로 남기거나(`active`), 무엇을 남겼을지 기록한다(`shadow`) | 민감 정보를 제거한 그 결과들의 텍스트와 마지막 프롬프트(앞 400자) |

민감 정보 제거(scrubbing)는 비밀처럼 생긴 문자열, `NAME=value` 형태의 비밀, 이메일 주소, 사용자의 홈 폴더 경로를 지운 뒤, 한국어 개인정보를 `[전화번호]` 같은 라벨로 바꾼다. 두 번째 단계는 [maskingtape](https://github.com/ChoHyeonChan/maskingtape) main 커밋 2802949(Apache-2.0)을 TypeScript로 옮긴 것이며(`hooks/pii/`), 입력 2,614건에서 원본과 결과가 같은지 확인했다. 이름은 규칙만으로 찾으며, 원 저장소는 그 재현율을 0.966으로 밝힌다. 길이 제한이 있는 텍스트는 먼저 가리고 나중에 자르며, 라벨 중간에서는 자르지 않는다.

### 블록: 웹 읽기

웹 읽기와, `fold: on`일 때의 접힌 결과의 블록 유지는 텍스트를 블록(문단, 목록 항목, 표의 행, 코드 블록, 최대 40줄의 출력 묶음)으로 나누고, 블록마다 그 위의 제목 경로를 붙인다. 그다음 어떤 블록이 질문에 답하는지 Jev에게 두 단계로 묻는다. 먼저 블록 묶음마다 요청을 한 번 보내고, 후보가 된 블록은 앞뒤 텍스트와 함께 다시 묻는다. 남기는 블록은 바꿔 쓰지 않고 원문 그대로 인용한다. 텍스트 전체는 아카이브에 남으므로, 잘못 판단된 블록도 `read_coordinate` 한 번이면 다시 볼 수 있다. 블록 나누기와 판단은 [jevfetch](https://github.com/a2sys-ai/jevfetch)(MIT, 커밋 167fe8f)에서 옮겨 왔고, 질문과 임계값은 바꾸지 않았다. 이 두 게이트는 텍스트에 대한 설명이 아니라 텍스트 자체를 보내는 게이트다.

`web_read`의 출력은 모델에게 다음처럼 보인다.

```text
# web_read: https://www.rfc-editor.org/rfc/rfc9110.html
# status: filtered (blocks are quoted from the page; '##' lines are the page's heading path)
# 5/2122 blocks, about 387 of 117469 tokens
# whole page: read_coordinate("web-mh3k2a07")
## HTTP Semantics > 15. Status Codes > 15.5. Client Error 4xx > 15.5.20. 421 Misdirected Request
The 421 (Misdirected Request) status code indicates that the request was directed at a server that is unable or unwilling to produce an authoritative response for the target URI. ...
```

`fold: on`이면 접힌 결과의 블록 유지도 같은 판단을 쓴다. 블록을 남긴 접기는 포인터 아래에 필요한 줄이 붙은 모습이다.

```text
[folded Read · hooks/register.ts · 598 lines — read_coordinate("toolu_…")]
[kept from the original, verbatim; the rest is in read_coordinate]
   441	    const below = await next(e)
   ...
```

블록은 판단이 답을 찾았고 남길 블록이 결과의 절반 이하일 때만 남긴다. `foldBlocksBudgetMs`(10초)가 압축이 판단을 기다리는 시간의 상한이며, 그때까지 판단이 끝나지 않은 결과는 포인터만 남기고 접는다. 접기 관련성이 `active`이면 블록 판단은 접힌 결과 안에서만 일어난다. 통째로 남긴 결과를 블록 단위로 다시 묻지 않는다.

### 켜는 방법

1. [TypeSafe 콘솔](https://console.typesafe.ai/home)에서 키를 발급받는다.
2. 플러그인에 키를 넘긴다. 아래 순서로 처음 찾은 키를 쓴다.
   1. `~/.conjev/key`: 키만 적은 파일이며, 모든 Claude Code 프로필이 읽는다.
   2. 플러그인의 보안 설정: 셸에서 `claude plugin configure conjev@conjev`로 넣는다(프로필마다 따로 보관된다).
   3. 플러그인 폴더에 있는 `.env`의 `TYPESAFE_API_KEY=` 줄
   4. `TYPESAFE_API_KEY` 환경 변수
3. `/jev-consent yes`로 동의한다. `auto`로 남아 있는 게이트는 실행 중인 세션에서 바로 켜진다. `/jev-consent no`는 다시 끈다.
4. 게이트를 직접 정하려면 `/config`의 conjev 항목, `settings.json`, 또는 `~/.conjev/config.json`을 쓴다. 공유 파일은 아래 `options`와 같은 키를 쓰고, 모든 프로필이 읽으며, `/config`를 포함한 프로필 자체의 값보다 우선한다. 이 파일은 감시되므로, 바꾸면 다시 시작하지 않아도 실행 중인 세션에 반영된다.

   ```json
   {
     "pluginConfigs": {
       "conjev@conjev": {
         "options": {
           "stopGate": "shadow",
           "toolGate": "shadow",
           "toolJev": "shadow",
           "instructions": "shadow"
         }
       }
     }
   }
   ```

5. `/jev-report`를 읽고 `/jev-mark`로 기록에 라벨을 붙인다([기록과 라벨](#기록과-라벨) 참고).

키가 없으면 상태 줄에는 `jev: no key`만 표시되고 아무것도 전송되지 않는다. 도구 게이트 floor는 키가 필요 없다. 그 밖의 경우 판단 계층의 상태 줄은 어떤 게이트가 무언가를 기록하기 전까지 비어 있다. Claude Code는 모든 플러그인 상태 줄에 경고 표시를 붙여 그리고 플러그인은 이를 바꿀 수 없기 때문에, 게이트가 켜져 있다는 말만 있는 상태 줄은 오류처럼 보이기 때문이다. 상태는 플러그인 상태 줄이 아니라 입력창 아래 안내 줄 끝에 `conjev:`를 앞에 붙여 흐리게 표시되므로 경고 표시가 붙지 않는다. 무언가 기록되면 상태는 `jev 42, 1 failed · floor 2 hits`처럼 합계 한 줄로 표시되고, `shadow`로 둔 게이트가 있으면 그 이름이 뒤에 붙는다. 게이트별 건수는 `/jev-report`에서 본다. `toolGate: active`에서는 에이전트가 플러그인의 `.env`나 Claude 설정 파일에 쓸 수 없으므로, 이 파일들은 사용자가 직접 설정한다. `~/.conjev/` 안에서 플러그인이 쓰는 것은 `state/` 아래의 기록과 사용자의 두 답 `consent.json`, `onboarding.json`뿐이다. `config.json`과 `key`는 사용자가 쓴다.

<details>
<summary>Stop 게이트 상세</summary>

1. 사용자 설정의 Stop 훅이 먼저 실행된다. 그중 하나가 막으면 그 결과를 따른다.
2. 다음은 판단하지 않는다: 재진입, plan 모드, 백그라운드 또는 예약 작업, 서브에이전트, 마지막 문장이 질문인 경우, 조건이 붙은 문장("알려주시면 처리하겠습니다", "once the checks pass…").
3. 규칙이 예고로 끝나는 문장을 찾고, Jev에게 `announce`와 `report` 가운데 하나를 고르는 양자택일 질문을 한다.
4. `shadow`에서는 턴이 즉시 끝나고 판단은 나중에 기록된다. `active`에서는 `stopThreshold`(0.7) 이상으로 `announce`가 나오면 모델을 다시 작업으로 돌려보낸다. 모델은 지금 그 일을 하거나, 사용자에게 무엇이 필요한지 분명히 말해야 한다.

</details>

<details>
<summary>도구 게이트 상세</summary>

- **공급자 신뢰.** 모든 신호가 일치할 때만 first-party로 본다: Anthropic 자격 증명이 있고, `HTTPS_PROXY`/`HTTP_PROXY`가 없고, `NODE_EXTRA_CA_CERTS`가 없고, Bedrock/Vertex/Foundry가 아니며, `ANTHROPIC_BASE_URL`이 비어 있거나 `https://*.anthropic.com`이어야 한다. 로컬 프록시는 `trustedProxies`에 등록되지 않았다면 외부로 본다. `providerTrust: external`은 외부로 강제하며, first-party로 강제하는 설정은 없다.
- **비밀 파일.** `.env`와 `.env.*`(`.example`, `.sample`, `.template`, `.tpl`, `.dist` 제외), `*.env`, `~/.ssh`(`*.pub`과 `known_hosts` 제외), `~/.aws`, `~/.gnupg`, gcloud, `~/.kube/config`, `~/.docker/config.json`, `~/.config/gh/hosts.yml`, Codex와 Claude의 자격 증명 파일, `.netrc`, `.npmrc`, `.pypirc`, `.pgpass`, `.git-credentials`, `*.pem`, `*.p12`, `*.pfx`, `*.kdbx`, `*.keystore`, `*.jks`, `id_rsa`와 그 계열, `~/.opencodex` 아래 프록시 토큰 파일, `/proc/<pid>/environ`. `~`, `$HOME`, `..`, 심볼릭 링크를 따라가 실제 경로로 판정한다.
- **셸.** Bash 명령의 모든 인자를 검사하며, git pathspec, `--opt=path`, 리다이렉트도 포함한다. `env`, `printenv`, `export -p`, `security … -w`, `gh auth token`도 대상이다.
- **보관된 원본.** 외부 세션에서 게이트가 켜져 있으면, `read_coordinate`는 보관된 결과를 만든 원래 호출을 그 호출이 받았을 판정과 똑같이 판정한다. 아직 존재하는 경로라면 그 경로가 가리키는 대상까지 따라간다. 아카이브 폴더를 직접 읽는 것도 같은 방식으로 거부한다. 따라서 앞서 접힌 비밀 파일은 어느 쪽으로도 다시 나오지 않는다.
- `active`에서 가드가 고장 나면 호출을 거부한다. `toolJev`는 대상과 세션마다 한 번만 묻고, floor가 지정한 경로에 대해서는 묻지 않는다.

</details>

<details>
<summary>조건부 지시 상세</summary>

Claude Code는 이미 경로에 따라 지시를 불러온다(`paths:`가 있는 `.claude/rules/*.md`, 하위 폴더의 CLAUDE.md). fragment는 사용자가 무엇을 요청하는지처럼 경로로는 알 수 없는 조건을 위한 것이다. fragment는 `fragmentsDir`(기본값 `~/.agents/fragments`)에 두는 Markdown 파일이며, 최대 24개, 각각 최대 4 KB까지 둘 수 있다.

```markdown
---
when: The person asks for prose meant for human readers, such as a report, an email or documentation.
keywords: report, email, 보고서
---
Lead with the conclusion. One idea per paragraph. Cut filler.
```

- **한 번 첨부하면 유지된다.** fragment는 조건을 처음 충족한 프롬프트에 덧붙고 대화 안에 계속 남으므로 캐시된 prefix가 유지된다. 플러그인은 각 프롬프트 전에 다음 요청에 여전히 실려 있는 fragment와, 실행 중인 턴 뒤에 대기 중인 프롬프트에 첨부된 fragment를 센다. 접기만 한 압축은 fragment를 유지하고, 엔진이 요약한 압축은 fragment를 버린다. 버려진 fragment만 다시 첨부될 수 있다.
- **키워드가 맞으면 Jev 없이 결정한다.** 그렇지 않으면 요청 한 번으로 아직 첨부되지 않은 모든 fragment를 묻고, `instructionThreshold`(0.95) 이상이면 첨부한다. `pin: true`를 쓰면 fragment가 system prompt 끝의 고정된 절 하나에 들어간다.
- 사용자가 직접 쓴 프롬프트만 판단한다. 조건은 좁게 쓴다. 범위가 넓은 산문 조건은 "이 파일이 무엇을 보여 주는지 한 문장으로 말해 줘" 같은 질문에서도 0.92~0.96이 나왔다.
- `examples/fragments/`에 복사해서 쓸 수 있는 범용 fragment 세 개가 있다.

</details>

<details>
<summary>접기 관련성 상세(<code>fold: on</code>)</summary>

압축 시점에는 어차피 prompt cache를 다시 만들기 때문에, 무엇을 남길지 판단해도 캐시 비용이 더 들지 않는다. 접기 대상이 될 수 있는 가장 큰 결과(최소 `minFoldChars`) 최대 48개에 대해, 사용자의 현재 요청에 그 결과가 아직 필요한지 Jev에게 묻는다. 이때 결과는 도구, 대상, 크기로만 보여 준다. 각 기록에는 접기가 그 결과를 어떻게 처리했는지와, 그 결과가 더는 필요 없다는 Jev의 확률이 담긴다. `shadow`에서는 여기까지다. `active`에서는 사용자가 요청한 압축에서 접기 전에 이 질문을 던진다. 대상은 최근 구간을 따지지 않았다면 규칙이 접었을 모든 결과이며, 그 답으로 접기를 정한다. Jev가 답하지 않은 결과는 규칙이 정한다.

</details>

### 기록과 라벨

- `/jev-report`: 게이트별로 기록, 이유별 건너뜀, 커버리지, 종류별 실패, 지연 시간(게이트별 Jev와 훅의 p50·p95, 시간 초과 건수), 토큰, Cohen's kappa를 포함한 규칙 대 Jev 비교표, 라벨이 없는 불일치, 그리고 라벨이 붙은 뒤에는 여러 임계값에서의 precision과 recall을 보여 준다.
- `/jev-mark <id> y|n`: 기록에 직접 라벨을 붙인다.
- 키가 있든 없든 압축마다 기록이 남는다: 트리거, 턴을 붙잡은 시간, 요약이 실행됐는지, 그리고 요약이 실행됐다면 엔진이 센 압축 전후의 창 크기(접기만 한 압축에는 토큰 수가 없다). `/jev-report`의 `compact` 항목에서 볼 수 있으며, 한 압축에서 다음 압축까지의 프롬프트 수, 턴 수, 시간도 함께 나온다. 사용자 자신의 세션에서 엔진이 직접 센 값이므로, 압축 설정을 바꿀 때 판단 근거로 삼을 값이다.

Stop 게이트를 `active`로 바꾸기 전에 양성 라벨 50개 이상과 음성 라벨 100개 이상을 모으고, 그 라벨에서 precision이 0.9 이상인 임계값을 찾는 것을 목표로 한다. 게이트도 이를 스스로 점검한다. 판단 150개에 라벨이 붙으면 precision을 계산하고, 0.9 미만이면 `active`인 Stop 게이트를 `shadow`로 낮추고 알린다. 이 강등은 세션이 바뀌어도 유지되며, `/jev-report`가 언제 왜 낮췄는지 보여 준다. 다른 게이트는 강등하지 않는다. 규칙과 일치한다는 것만으로는 근거가 되지 않는다. 규칙은 턴 종료의 약 5%만 표시하므로, 항상 "아니요"라고 답하는 게이트도 약 95%는 일치하기 때문이다.

`scripts/replay.ts`(`bun`으로 실행)는 과거 transcript(`$CLAUDE_CONFIG_DIR/projects` 또는 `~/.claude/projects`)를 오프라인에서 Stop 규칙에 다시 통과시킨다. `--jev N`을 주면 민감 정보를 제거한 문단을 최대 N개까지 Jev에 보낸다.

### Jev 비용

모든 게이트를 켜도 세션 하나에 드는 비용은 최대 약 $0.03이며, 작성자가 Claude Max 20x 요금제로 최근 30일 동안 쓴 양이라면 $0.28~1.00이 들었을 것이다. 더 큰 비용은 시간이다. `active`에서는 판단 대상인 턴 종료, 외부 세션에서 각 대상에 대한 첫 호출, 첨부되지 않은 fragment가 있고 키워드가 맞지 않는 프롬프트가 각각 Jev를 기다린다. 보통 0.2~0.35초, 최대 2초(`timeoutMs`)가 걸린다.

## 지시 파일

Claude Code는 대화를 시작할 때와 압축할 때마다 지시 파일을 통째로 불러온다. 대상은 사용 중인 프로필의 사용자 `CLAUDE.md`, 프로젝트의 `CLAUDE.md`와 `AGENTS.md`, 이 파일들이 `@`로 가져오는 모든 파일, 그리고 작업 폴더의 모든 상위 폴더에 있는 `.claude/CLAUDE.md`다. 마지막 규칙 때문에 홈 폴더 안에서 실행한 세션은 `~/.claude/CLAUDE.md`를 프로젝트 파일로도 불러온다. 다른 프로필의 `CLAUDE.md`(예: `~/.claude-3/CLAUDE.md`)가 그 파일의 사본이라면 같은 내용이 두 번 로드된다.

**이 문제는 플러그인 없이 해결할 수 있다.** 자체 사본을 두는 `~/.claude` 이외의 각 프로필에서 공유 파일을 제외한다.

```json
{ "claudeMdExcludes": ["/Users/you/.claude/CLAUDE.md"] }
```

이 설정을 `~/.claude/settings.json` 자체에는 절대 넣지 않는다. 그 프로필에서는 같은 파일이 프로필 자신의 사용자 파일이므로, 넣으면 프로필이 그 파일을 잃는다. 작성자의 환경에서는 이 설정으로 첫 요청이 69,152 토큰에서 66,655 토큰으로 줄었다(5.9k자 분량의 OMC 블록이 두 번이 아니라 한 번만 로드되었다).

**`instructionFilter`**(`auto`, `off`, `shadow`, `active`, 기본값 `auto`)는 그러고도 남는 중복을 처리한다. 이 설정은 엔진의 `prompt.context` 훅을 쓰는데, 이 훅은 지시 파일이 전송되기 직전에 그 내용을 플러그인에 넘긴다. 플러그인은 지시 파일을 제목과 태그 블록 단위의 chunk로 나누되 코드 펜스는 쪼개지 않고, 그다음 아래와 같이 처리한다.

- **바이트 단위로 똑같이 두 번 로드된 chunk**(공백 차이는 무시): `active`에서는 뒤쪽 사본을 빼고 그 자리에 한 줄짜리 노트(`[conjev: left out "…", loaded from …]`)를 넣어 모델이 이를 알 수 있게 한다. 버전이 다른 OMC 블록이 두 개 있으면 오래된 쪽을 뺀다. 조직(`managed`) 파일과 auto-memory 색인은 절대 바꾸지 않는다.
- **나머지에 대한 Jev의 판단은 `active`에서는 Jev가 답한 뒤부터 적용하고, `shadow`에서는 기록만 한다.** 요청이 전송된 뒤에 Jev에게 각 chunk가 거의 모든 요청에 필요한지 묻고, 사용자 수준의 각 chunk에 대해서는 앞선 chunk들이 이미 그 내용을 모두 말하고 있는지 묻는다. `/jev-report`는 그 판단에 따라 빼거나 미룰 chunk와 이유를 나열한다. 다음 규칙은 절대 빼거나 미루지 않는다: 정체성, 언어, 자율 실행과 승인, 질문에 먼저 답하기, 셸, git, API 키, 브라우저, 제목에 `중복`이나 `강조`가 들어간 모든 절(작성자가 의도적 반복을 표시하는 방식이며, 다르게 쓴 제목은 Jev가 판단한다), 그리고 OMC 블록. Orca 절은 Jev가 아니라 실행 환경이 결정한다.
- **누락 위험(would-miss):** 슬래시 명령을 포함한 모든 프롬프트에 대해, 미뤄 둘 chunk가 그 프롬프트에 해당하는지 Jev에게 묻는다. 그런 chunk와 관련된 종류의 도구 사용(브라우저, 웹 조회, `orca`, `claude -p`)도 기록하며, `/jev-report`는 해당 chunk가 아직 첨부되지 않은 상태로 그런 작업이 시작된 횟수를 센다.

`active`에서는 Jev가 covered이거나 일부 작업에만 필요하다고 판독한 chunk(0.95 기준)가 같은 파일을 다음에 로드할 때부터 빠지고, 빠진 자리마다 Jev가 뺐다는 것과 그 이유를 적은 줄이 남는다. Jev는 요청이 나간 뒤에 답하므로 첫 로드는 그대로 나간다. 이것이 자신에게 안전한지는 `/jev-report`의 누락 위험 비율을 보거나 covered chunk에 `/jev-mark`로 라벨을 붙여 판단한다. 이 판단은 백그라운드에서 수백 밀리초를 쓸 뿐 요청 경로에는 비용을 더하지 않는다. `prompt.context` 자체는 약 30 ms가 걸린다.

## 프로젝트 상태와 메모리

압축 요약은 결코 정본이 아니며, 정본은 프로젝트가 관리하는 파일이다. 플러그인은 세 가지 파일을 각각 존재할 때만 사용하고, 직접 쓰지는 않는다. 파일은 에이전트가 쓰고, 플러그인은 확인하고 가리키기만 한다.

| 파일 | 담는 내용 | 작성 시점 |
| --- | --- | --- |
| `INTENT.md` | 사용자가 원하는 것을 에이전트가 이해한 내용: 목표, 완료 조건, 범위, 제약, 열린 질문. 각 줄은 사용자 자신의 말을 인용한다 | 사용자가 목표를 말하거나 바꿀 때 |
| `PHASE.md` | 사용자가 읽는 상황판: 지금 할 일, 다음 할 일, 사용자가 필요한 일, 근거와 함께 완료된 일, 재개 메모. 에이전트가 여럿이면 누가 무엇을 맡았는지. **Handoff** 절은 작업을 이어받는 세션을 위한 것이다: 브랜치와 워크트리, 커밋을 push했는지, 커밋하지 않은 변경, 가장 먼저 실행할 명령, 되풀이하면 안 되는 것 | 단계가 끝나거나 막혔을 때, 사용자가 결정했을 때, 커밋 상태가 바뀔 때, 핸드오프 전, 플러그인이 요청할 때 |
| `sessions/<date>-<slug>.md` | 에피소드: 무슨 일이 언제 있었는지와 그 근거(경로, 커밋, `read_coordinate` id) | 작업 단위마다, 추가만 한다 |

- **상황판이 없는 프로젝트에는 만들기를 제안한다.** 사용자가 첫 프롬프트를 쓰면, 플러그인이 Claude Code 자체의 대화상자로 `PHASE.md`를 만들지 묻는다. 파일은 그 뒤에 에이전트가 쓴다. 3시간 동안 답이 없으면 동의한 것으로 본다. 질문은 한 번만 한다. 거절도 동의도 세션을 넘어 기억한다. 물어볼 사람이 없는 실행(`claude -p`)은 절대 동의로 보지 않는다.
- **상황판은 저장소와 대조한다.** 압축 전에 상황판 갱신을 요청할 때, `git status`가 보여 주는 것 가운데 상황판의 Handoff 절에 적혀야 할 것도 함께 알린다. push하지 않은 커밋, 커밋하지 않은 변경이 있는 파일, 또는 Handoff 절이 아예 없는 상황판이 그것이다.
- `/conjev:project-state`는 `INTENT.md`와 `PHASE.md`를 관리한다. 혼자 작업할 때와 여러 에이전트 세션이 함께 작업할 때 모두 쓸 수 있으며, 상황판 하나를 일관되게 유지하는 규칙과 작업을 이어받는 세션이 따를 절차를 담고 있다.
- `/conjev:consolidate`는 한동안 진행한 작업을 오래 남는 메모리로 정리한다. 상황판과 에피소드를 갱신하고, 반복되는 절차는 프로젝트 스킬로 만들며, 오래 유지할 원칙은 사용자가 동의하면 `AGENTS.md`에 넣는다. 반복되는 결정론적 절차는 코드로 만들도록 제안한다. [just-dag-it](https://github.com/ysys143/just-dag-it)을 참고한다.

## 압축

기본값에서는 모든 압축(`/compact`, 또는 창이 차서 엔진이 시작하는 압축)이 Claude Code 자체 요약이다. 요약은 transcript 전체를 대상으로 하며, `/compact` 뒤에 사용자가 입력한 내용만 지시로 받는다. 플러그인은 그 곁에서 네 가지를 한다.

1. **요약 전에** 요약이 대체할 대화를 `conversation-<id>` 항목 하나로 보관하고, 요약 뒤에 그 항목을 가리키는 줄을 하나 붙인다. 그래서 `read_coordinate`로 그동안 나눈 말을 다시 읽을 수 있다.
2. **요약 뒤에**, 프로젝트가 `INTENT.md`, `PHASE.md`, 에피소드 로그([프로젝트 상태](#프로젝트-상태와-메모리))를 관리하고 있으면 노트를 덧붙인다. 노트에는 다시 읽을 파일과 그 순서가 적히고, 상황판이 있으면 그 Handoff 절이 작업을 이어받는 세션이 가장 먼저 읽는 곳이라는 안내도 들어간다.
3. **압축을 기록한다.** 트리거, 턴을 붙잡은 시간, 압축 전후의 창 크기가 남고, `/jev-report`의 `compact` 항목에서 볼 수 있다.
4. **`read_coordinate`** 는 요약 뒤의 줄이나 접힌 포인터가 알려 주는 id로 보관된 원본을 돌려준다. `offset`과 `limit`을 지정하지 않으면 한 번에 400줄씩 돌려준다. `query`를 주고 Jev 키가 있으면, 그 질문에 해당하는 구절만 원문 그대로 돌려주고 빠뜨린 범위를 줄 번호로 알려 준다. `query`, `offset`, `limit`, `full`이 모두 없으면 사용자의 마지막 요청을 `query`로 쓴다. `full: true`는 원본 전체를 돌려준다. 키가 없으면 `query`를 줘도 원본 전체를 돌려준다. 아무것도 고르지 않은 조각을 주는 것보다 낫기 때문이다.

| 설정 | 기본값 | 이유 |
| --- | --- | --- |
| `intentFile` | `INTENT.md` | 사용자가 원하는 것을 에이전트가 이해한 내용이다. 비우면 끈다 |
| `phaseFile` | `PHASE.md` | 상황판이자 핸드오프 문서다. 비우면 끈다 |
| `episodeDir` | `sessions` | 에피소드 로그 폴더다. 비우면 끈다 |
| `imageMaxPx` | 0 | 긴 변이 이보다 큰 이미지를 축소 사본으로 읽는다. 0이면 끈다 |

**이미지.** 이미지 한 장은 대략 가로 × 세로 / 750 토큰이 들고 최대 약 1,550 토큰이다. 이미지는 압축될 때까지 transcript에 남고 접기도 이미지는 건드리지 않으므로, 세션 초반에 읽은 스크린샷은 그때까지 요청마다 비용이 든다. `imageMaxPx`를 설정하면, 긴 변이 그보다 큰 PNG나 JPEG를 `Read`할 때 축소한 사본을 대신 읽는다. 축소에는 `sips`(macOS)나 ImageMagick(`identify`, `convert`. Linux)을 쓴다. 사본은 아카이브 옆에 보관하고 다시 쓴다. 크기를 읽지 못하거나 축소가 실패하면 원본을 읽는다. PDF와 사용자가 붙여 넣은 이미지는 크기가 바뀌지 않는다.

### 접기

`fold: on`(`/config`나 `~/.conjev/config.json`)이면 압축에 요약 대신 접기로 응답한다. 크고 오래된 도구 결과를 아카이브에 기록한 뒤 한 줄 포인터로 바꾸고, 접기만으로 부족할 때만 요약한다. 기본으로 꺼 둔 이유는 [필드 테스트](docs/experiment/compaction-field-test.ko.md)에 있다. 게이트를 켠 요약이 같은 비용으로 더 높은 점수의 보고서를 썼고, 대화 중에 준 지시는 접기가 가장 잘 지켰다.

![`fold: on`일 때. 압축 전에는 최근 10개 모델 턴보다 오래된 큰 도구 결과 두 개가 transcript를 채우고 있다. 접은 뒤에도 메시지는 그대로 남고 두 결과만 한 줄 포인터로 바뀐다. 원본은 디스크 아카이브에 있고 read_coordinate가 이를 돌려주며, 노트가 모델에게 INTENT.md와 PHASE.md를 다시 읽으라고 안내한다.](docs/fold.svg)

모델이 실제로 보는 포인터의 예시는 다음과 같다. id는 `read_coordinate`에 넘기는 값이다.

```text
[folded Read · src/billing/invoice.ts · 1201 lines — read_coordinate("toolu_01J7igoRSuY8xw8F8skCSEY3")]
```


도구 결과는 완료되었고 클 때 접힌다. 구체적으로는 최근 `keepRecentTurns`개 모델 턴보다 오래되었고, 길이가 `minFoldChars` 이상이며, `keepErrorsUnder`보다 짧은 오류가 아니고, `keepTools`에 속한 도구의 결과가 아니어야 한다. 포인터가 원본보다 길어지는 결과는 접지 않으며, 이미지나 문서가 든 메시지의 결과도 접지 않는다([한계](#한계) 참고).

1. **압축 시점**(`/compact`, 엔진의 자동 압축, 또는 4단계)에 플러그인이 엔진의 요약보다 먼저 응답한다. 조건을 충족한 결과는 아카이브에 기록된 뒤 포인터로 바뀐다. 오래된 도구 호출의 큰 본문도 같은 규칙(본문 텍스트 기준)으로 접힌다. `Write`의 content, `Edit`의 문자열, 긴 `Bash` 명령은 `[folded input · Write · src/a.ts · 4200 chars — read_coordinate("toolu_…:input")]`가 된다. 나머지 메시지는 손대지 않고 그대로 돌려준다.
2. **접기만으로 부족하면**, 즉 접은 뒤에도 창의 60% 이상을 차지하면 엔진이 최근 구간보다 오래된 부분만 요약한다. 최근 턴은 규칙대로 접힌 상태로 그대로 이어 붙는다. 그다음 플러그인이 요약이 잃어버릴 두 가지를 되돌려 놓는다. 하나는 요약된 구간에서 사용자가 쓴 모든 프롬프트(순서 그대로)이고, 다른 하나는 접힌 원본 각각의 포인터를 모은 메시지 하나다. 그래서 모델은 원본마다 다시 찾아갈 길을 잃지 않는다. 접을 결과가 없거나 아카이브에 쓸 수 없으면([데이터와 개인정보](#데이터와-개인정보)) 엔진이 transcript 전체를 요약한다. 요약이 대체하는 부분은 요약 전에 `conversation-<id>` 항목 하나로 아카이브에 보관되고 포인터 메시지가 그 항목을 가리키므로, 대화 자체도 `read_coordinate`로 다시 읽을 수 있다. 요약에는 사용자가 `/compact` 뒤에 쓴 지시가 먼저 전달되고, 그 뒤에 플러그인의 요청(사용자의 요청과 결정은 사용자의 말로, `[folded …]` 줄은 그대로 남길 것)이 덧붙는다. 60%는 고정 비율이며 `foldAtPercent`와는 무관하다. 또한 실제 토큰 수가 아니라 transcript의 문자 수로 추정한 값을 기준으로 한다.
3. **요약은 상황판을 기다린다.** 프로젝트에 `PHASE.md`나 에피소드 로그가 있고([프로젝트 상태](#프로젝트-상태와-메모리)) 지난 압축 이후 갱신되지 않았다면, 요약을 미루고 에이전트에게 갱신을 요청한다. 접기는 그대로 진행한다. 요약은 사용자가 한 말을 에이전트가 이해한 내용으로 바꾸는데, 그 이해가 적혀 있는 곳이 상황판이기 때문이다. 요청을 두 번 한 뒤에는 묻지 않고 요약한다. 이 요청에 응하는 턴은 Stop 게이트가 붙잡지 않는다.
4. **대기 상태에 들어가는 시점**, 즉 창이 `foldAtPercent` 이상 찬 상태로 턴이 끝나면 플러그인이 직접 압축을 시작한다. 다만 압축할 때마다 prompt cache를 한 번 다시 만들어야 하므로, 접기로 transcript가 `minSavedPercent` 이상 줄어들 때만 실행한다. 시작하기 전에 30초를 기다리고, 그사이 사용자가 프롬프트를 쓰면 물러난다. 그래서 사용자의 다음 요청이 요약 뒤에 줄을 서지 않는다. 요약이 도는 동안에는 상태 줄에 그 사실이 표시된다.
5. **압축이 끝난 뒤**, 접은 결과가 있었거나 프로젝트가 위의 파일을 관리하고 있으면 노트를 덧붙인다. 노트에는 접은 결과의 개수와 다시 읽어야 할 프로젝트 파일이 적히고, 상황판이 있으면 그 Handoff 절이 작업을 이어받는 세션이 가장 먼저 읽는 곳이라는 안내도 들어간다.

| 설정(`fold: on`) | 기본값 | 이유 |
| --- | --- | --- |
| `keepRecentTurns` | 10 | 진행 중인 작업은 여전히 가장 최근 모델 턴을 읽는다. 모델 턴은 응답 하나와 그 도구 호출, 결과를 묶은 단위다. 사람 프롬프트로 세면 한 번 시작해 두고 맡기는 세션(`/goal`)에서는 아무것도 접히지 않는다 |
| `minFoldChars` | 1000 | 측정한 세션에서 결과의 44%가 전체 도구 출력의 90%를 차지했다 |
| `keepErrorsUnder` | 2000 | 짧은 오류가 남아 있어야 모델이 같은 실수를 반복하지 않는다 |
| `keepTools` | `TodoWrite,AskUserQuestion,ExitPlanMode` | 작고, 현재 결정 사항을 담고 있다 |
| `foldAtPercent` | 60 | 턴이 끝난 뒤 스스로 접기를 시작하는 시점이다. 0이면 끈다 |
| `minSavedPercent` | 20 | 이 비율 이상 줄어들 때만 스스로 접는다 |

`/conjev:tune-policy`는 접기 코드 자체(`policy_report`)로 사용자의 세션을 측정하고, 사용자에게 몇 가지를 물은 뒤, 고른 값을 현재 값과 나란히 dry-run해 보여 준다. 사용자가 동의한 뒤에만 값을 적용한다(`set_policy`는 위 표의 접기 설정만 쓰고 그 밖의 설정은 건드리지 않는다).

## 비교

- **Claude Code 자체의 압축**은 대화를 요약으로 바꾼다. conjev는 그 요약을 그대로 쓰면서, 요약이 대체하는 대화를 보관하고 요약 뒤에 모델이 프로젝트 파일을 다시 읽도록 안내한다. `fold: on`이면 오래된 도구 결과를 먼저 접고, 접기만으로 부족할 때만 요약한다.
- **jev-harness**는 이 플러그인의 출발점으로, Stop 게이트, 도구 게이트, 조건부 지시를 갖고 있었다. conjev는 여기에 지시 필터, 웹 읽기, 브라우저 라우팅, 동의와 첫 실행 안내, 프로필 사이에 공유하는 설정, 압축 시점의 보관과 노트를 더한다.
- **메모리 플러그인**은 세션을 넘어 배운 내용을 자체 저장소에 보관한다. conjev는 세션 안에서 동작하며, 오래 남겨야 할 내용은 에이전트가 프로젝트 자체의 파일(`INTENT.md`, `PHASE.md`, `sessions/`)에 기록한다.

## 데이터와 개인정보

플러그인이 보관하는 모든 것은 사용자만 열 수 있는 폴더 하나 아래에 있다. 모든 폴더는 그 안에 무언가를 쓰기 전에 권한 700으로 만들어지고, 세션 도중 지워졌다면 같은 방식으로 다시 만들어진다. 이 과정이 실패하면 아무것도 쓰지 않고 엔진이 요약한다.

```text
~/.conjev/
  config.json                            모든 프로필이 함께 쓰는 설정(사용자가 씀)
  key                                    모든 프로필이 함께 쓰는 Jev 키(사용자가 씀)
  consent.json                           /jev-consent에 대한 사용자의 답
  onboarding.json                        첫 실행 설정 안내를 마쳤거나 거절한 기록
  state/
    archive/<session>/<id>.json          보관된 원본(conversation-<id>인 요약된 대화, web-<id>인 페이지,
                                         접힌 결과와 입력), 삭제하지 않음
    records/<session>/<gate>/<id>.json   판단 기록, 14일 보관
    records/labels/labels/<id>.json      사용자가 붙인 라벨, 보관
    replay/                              replay 출력
    shrunk-<path>                        축소한 이미지 사본(imageMaxPx), 재사용
```

이번 릴리스 전에는 상태를 `~/.local/state/context-harness/`에 두었다. 세션이 시작될 때마다 이 폴더를 `~/.conjev/state/`로 옮긴다. 새 폴더가 아직 없으면 통째로 옮기고, 둘 다 있으면 새 폴더에 없는 파일만 옮긴다(`rsync` 한 번). 양쪽에 다 있는 파일은 내용이 같으면 옛 폴더에서 지우고 다르면 옛 폴더에 남기며, 옛 폴더의 보관된 원본·기록·라벨도 계속 읽고 정리한다. 그래서 이전 릴리스로 도는 세션이 그곳에 쓴 것도 다음 시작 때 합쳐진다.

아카이브 파일에는 도구가 돌려준 내용이 그대로 담긴다. 기록에는 전송한 내용(민감 정보 제거 후), 판정, 소요 시간이 담긴다.

이름이 바뀌기 전에 접은 결과는 `~/.claude-context-fold/<session>/`에 남아 있다. 플러그인은 이 결과를 읽기만 하고 그곳에 쓰거나 지우지 않는다. `HOME`이 없으면 프로젝트 안에 쓰는 대신 아무것도 보관하지 않고 엔진이 요약하게 둔다. 보관된 내용을 지우려면 다음을 실행한다.

```sh
rm -rf ~/.conjev/state/archive/<session-id>   # 한 세션의 원본
rm -rf ~/.conjev/state ~/.local/state/context-harness ~/.claude-context-fold # 전부
```

플러그인은 다음을 오직 이 용도로만 쓴다: 네트워크(키가 있고, `jev`가 `on`이고, 게이트를 사용자가 직접 켰거나 `auto`에 사용자가 동의했을 때 Jev에만), 프로세스(자기 폴더에 대한 `mkdir`, `chmod`, `find`; 접기가 예정되어 있고 점검할 상황판이 있을 때 작업 폴더에서 읽기만 하는 `git status`; `imageMaxPx`가 설정된 상태에서 `Read`하려는 이미지에 대한 `sips`, 또는 `identify`와 `convert`), 환경 변수(`HOME`, `TYPESAFE_API_KEY`, 그리고 신뢰 판정이 읽는 프록시와 공급자 변수). 접기를 포함해 이 모두를 모듈 하나가 쓰기 때문에, 모듈이 쓰는 기능으로 모듈을 판단하는 정책은 접기 기능도 이 기능들과 함께 판단하게 된다.

## 한계

- 이 플러그인보다 먼저 로드되어 압축에 직접 응답하는 플러그인이 있으면 그 플러그인이 압축을 가져간다. 이때 이 플러그인은 그 압축을 보관하지도, 접지도, 판단하지도 않는다.
- 설정을 바꾸면 플러그인이 다시 로드되면서 카운터와 정리 요청 횟수가 처음부터 다시 시작된다.
- `shadow`에서는 아무것도 첨부하지 않으므로, 첨부되었을 fragment를 기억해 두었다가 압축 요약이나 대화 초기화를 볼 때만 잊는다. `active`에서는 대신 대화 내용을 센다.
- 지시 필터는 시작 시점과 압축 뒤에 로드되는 것만 본다. 하위 폴더의 `CLAUDE.md`와 `.claude/rules`는 Claude Code가 파일을 읽으면서 나중에 들어오므로 필터를 거치지 않는다.
- Stop 게이트의 강등은 플러그인 저장소에 남으며 플러그인이 되돌리지 않는다. 아직 되돌리는 명령은 없다.
- 한국어 개인정보 가운데 이름은 규칙만으로 찾는다. 원본 maskingtape가 보고한 재현율 0.966을 그대로 받아들이며, 이름 100개 가운데 약 3개는 가려지지 않은 채 Jev에 갈 수 있다.
- 첫 실행 설정 안내는 세션의 첫 프롬프트(`initialUserMessage`)로 시작한다. 자체 프롬프트가 있는 `-p` 실행에서는 어느 쪽이 먼저인지 엔진이 정한다.
- `imageMaxPx`는 `sips`(macOS)나 ImageMagick이 필요하다. 둘 다 없으면 이미지를 그대로 읽는다.
- `query`를 준 `read_coordinate`는 Jev 키가 필요하다. 키가 없으면 원본 전체를 돌려준다.
- `web_read`는 서버가 보내는 것을 최대 400만 자까지 읽는다. JavaScript는 실행하지 않고, PDF와 그 밖의 파일은 거부하며, 로컬과 사설망 주소는 절대 가져오지 않는다(`shadow`에서는 비밀처럼 생긴 값이 든 WebFetch URL도 가져오지 않는다). 주소는 적힌 그대로 검사한다. 그래서 사설 주소로 풀리는 공개 이름이나 사설 주소로 가는 리다이렉트는 가져온다. Claude Code가 직접 가져오고 리다이렉트도 따라가기 때문이다. HTML 판독기는 패키지를 쓸 수 없는 플러그인용으로 따로 작성했으므로, 형식이 깨진 페이지는 jevfetch와 다르게 나뉠 수 있다. 노트로 표시된 곁글은 따로 판단하지 않고 페이지 안에 남긴다. XML은 텍스트로 읽는다.
- 웹 읽기의 토큰 수는 추정값이다(ASCII 문자 약 네 개, 그 밖의 문자 하나를 토큰 하나로 센다). 플러그인에는 토크나이저가 없다.
- 브라우저 라우팅은 규칙만으로 도구를 찾는다. `PATH`(`which`)나 `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`, `~/.bun/bin`, `~/.npm-global/bin`에 있는 명령, 그리고 프로젝트의 `node_modules`나 브라우저 캐시에 있는 Playwright를 찾는다. 아무것도 실행하지 않고 디버깅 포트도 확인하지 않으므로, CDP 도구는 `browserCdp`에 적었을 때만 센다. 사용자의 권한 규칙이나 다른 플러그인의 훅은 읽을 수 없다. 그것들이 막는 도구는 `browserBlocked`에 적어야 하며, 적지 않으면 그 도구를 권할 수 있다.
- 아직 하지 않은 것: 첨부한 fragment가 답을 개선하는지 확인하는 것, 실제 예고 문장에 대한 Stop 게이트의 정확도를 재는 것, 설정에 따라 재압축 간격이 달라지는지 확인하는 것(비교 근거는 이제 `/jev-report`가 모은다).

`fold: on`일 때:

- 결과는 압축 시점에만 접힌다. 플러그인은 모델 요청을 턴마다 다시 쓸 수 없다.
- Claude Code는 이미 아주 큰 Bash 출력을 파일로 저장한다. 가장 큰 효과는 `Read`처럼 Claude Code가 출력을 통째로 남겨 두는 도구에서 나온다.
- "턴"은 모델 턴이다. 응답 하나가 여러 행으로 넘어와도 한 턴으로 세고, 자르는 지점은 호출과 그 결과를 갈라놓지 않는다.
- 서브에이전트의 transcript는 접지 않으며, 엔진이 미리 계산하는(precompute) 압축도 접지 않는다. 요약된 대화는 메인 대화의 것만 보관한다. 접힌 결과는 그것을 접은 세션에서만 읽을 수 있으며, `/clear` 뒤나 fork에서는 읽을 수 없다.
- 이미지나 문서가 든 사용자 메시지는 접지 않는다. 접기는 메시지를 행에서 다시 만드는데 행에는 이미지가 없어서, 접으면 그 이미지가 사라지기 때문이다. 그런 메시지의 큰 결과는 그 세션 내내 그대로 남으며, 접기 대상이었을 결과도 함께 남는다. 플러그인은 api 보기(`$.session.messages({ as: 'api' })`)에서 이미지를 확인하고, 그 보기를 얻지 못하면 아무것도 접지 않고 엔진이 요약한다.
- 플러그인은 `/compact`를 실행해 스스로 접기를 시작하므로, 그 명령이 transcript에 나타난다.
- 요약은 최근 구간보다 오래된 부분에만 실행된다. transcript에 `keepRecentTurns`보다 적은 수의 모델 턴만 있으면 오래된 부분이 없으므로, 접은 뒤에도 창의 60%를 넘는 경우 요약하지 않는다.
- 60% 판정은 transcript의 문자 수로 토큰을 추정한다. 이미지, 추론 블록, 시스템 프롬프트는 세지 않으므로 실제 창보다 낮게 나온다.
- 자동 접기는 30초를 기다린다. 그사이 프롬프트를 쓰면 그 순간을 가져간다. 타이머가 울릴 때 하는 판정은 단위 테스트로 덮여 있지만, 타이머 자체를 울리는 테스트는 없다. 테스트 런타임은 타이머 콜백을 즉시 실행하므로 "타이머 설정, 사용자가 씀, 타이머 울림" 순서를 만들 수 없다.
- `active`인 접기 관련성은 자동 압축도 Jev가 답할 때까지 붙잡는다. 결과 24개 묶음마다 최대 `timeoutMs`의 두 배까지 걸리며, 시간 안에 답이 없으면 그 결과들은 규칙이 정한다.
- 접힌 도구 입력은 그 assistant 메시지를 텍스트와 도구 호출만으로 다시 만들기 때문에, 그 오래된 턴의 추론 블록은 함께 사라진다.
- 접힌 결과의 블록 유지는 출력 줄을 40줄씩 묶으므로, 남긴 코드 블록에 정작 필요한 줄 주변의 줄이 함께 붙을 수 있다.

## 업그레이드

conjev는 각 아이디어를 시험하려고 따로 만든 두 플러그인, [context-fold](https://github.com/ysys143/context-fold)와 [jev-harness](https://github.com/ysys143/jev-harness)를 합친 것이다. 따로 있을 때는 압축 한 번에서 일어난 일을 서로 공유할 수 없었고, 로드 순서에 따라 두 번째 플러그인이 압축을 볼 수 있는지가 갈렸다. 이 플러그인을 설치하기 전에 두 플러그인을 모두 제거한다. 둘 중 하나와 함께 설치하면 접기나 Jev 전송이 두 번 일어난다.

- **context-harness에서 오는 경우**(0.0.3까지의 이 플러그인 이름): 세션이 시작될 때마다 `~/.context-harness/`를 `~/.conjev/`로 항목별로 옮긴다. 키, 동의, 설정 안내의 답, 설정 파일은 `~/.conjev/`에 없을 때만 옮기고, 상태는 위와 같이 합친다. 항목별로 옮기는 이유는 `~/.conjev/`가 일부만 담은 채 먼저 생겨 있을 수 있기 때문이다. 그래서 공유 키, 동의와 설정 안내에 대한 답, 설정, 상태가 그대로 이어지고 설정 안내를 다시 묻지 않는다. `claude plugin configure context-harness@context-harness`로 넣은 키는 옛 플러그인 이름 아래에 저장되어 있어 이어지지 않으므로, conjev 아래에 다시 넣거나 `~/.conjev/key`에 둔다. 명령은 이제 `/conjev:…`다.
- **context-fold가 접은 결과**는 계속 읽을 수 있다. `read_coordinate`는 같은 세션에 대해 자체 아카이브를 먼저 보고 그다음 `~/.claude-context-fold/<session>/`을 본다.
- **설정과 키**는 이어지지 않는다. conjev 아래에서 다시 설정한다. `/config`로 하거나, 모든 프로필에 한 번에 적용하려면 `~/.conjev/config.json`과 `~/.conjev/key`에 쓴다.
- **jev-harness 기록**(`~/.local/state/jev-harness/`)은 읽지 않는다. 그 기록의 접기 판정은 규칙의 사본에서 나왔는데, 이번 릴리스는 그 규칙을 접기 자체로 대체했다. 더 필요 없으면 그 폴더를 지운다.
- **jev-harness만 쓰고 있었다면** 새로 지시 필터, 웹 읽기, 브라우저 라우팅, 동의와 첫 실행 안내, 압축 시점에 요약된 대화의 보관과 노트를 얻는다. 접기는 `fold: on`으로 켠다.
- **context-fold만 쓰고 있었다면** 접기가 이제 기본으로 꺼져 있다는 점에 유의한다(`fold: on`으로 다시 켠다). 새로 `/jev-report`, `/jev-mark`, 게이트가 꺼져 있으면 그대로 통과시키는 모든 도구 호출의 훅, 세션 시작 때마다 14일 지난 판단 기록을 지우는 정리 기능을 얻는다.
- **바뀐 동작:** 이미 대화에 있는 fragment는 접기만 한 압축 뒤에 다시 첨부되지 않는다(jev-harness는 다시 첨부했다). 접기 판단 기록은 접기가 실제로 한 일을 적으며, 턴을 접기와 같은 방식으로 센다.

## 개발

```sh
claude --plugin-dir /path/to/conjev   # 플러그인을 로드한 세션
claude plugin test /path/to/conjev    # tests/*.test.ts
claude plugin validate /path/to/conjev
```

테스트는 333개다. 네 개는 연구용 상태 경로 선택, 개인·이전 기록 대체 읽기 거부, 아카이브 보호를 확인한다.

<summary>릴리스마다 테스트로 확인한 것</summary>

마지막 하나는 접기를 껐을 때도 압축 뒤의 노트가 남는지 확인한다. 노트를 지우거나 대체된 대화를 보관하지 않게 했을 때 각각 테스트가 실패했다. 그 전에는 328개였다. 턴을 모델 턴으로 세게 바꾸면서 네 개를 더했다: 한 번만 프롬프트를 받은 세션도 접힘, 자르는 지점 앞의 사람 프롬프트가 요약 너머로 넘어감, 여러 행으로 넘어온 응답 하나를 한 턴으로 셈, 자르는 지점이 호출 없는 결과를 남기지 않음. 뒤의 세 배선을 하나씩 되돌려 심었을 때 각각 테스트 하나가 실패했다. 그 전에는 324개였다. 그 앞의 세 개는 `fold: off`를 다루며, 그 배선 두 곳을 하나씩 되돌려 심었을 때 각각 테스트 하나가 실패했다: 압축이 여전히 접는 경우와 압축이 여전히 미리 시작되는 경우. 그 전에는 321개였고, 접기와 Jev를 기본으로 바꾸기 전의 254개보다 67개 많았다. 이 작업에서는 결함 39개를 잡아야 할 테스트와 함께 하나씩 심어 보았고, 매번 테스트가 하나 이상 실패했다: `auto`가 동의 없이 켜지거나 끝내 켜지지 않음; `jev: off`를 무시함; `/jev-consent`가 기록하지 않음; 첫 실행 안내가 시작되지 않거나, 마치거나 거절한 뒤에도 다시 시작함; 세션 중에 놓은 키가 `auto`를 켜지 않음; `/config`가 공유 파일보다 우선하거나 접기가 프로필의 정책을 계속 씀; 바뀐 공유 파일이 반영되지 않거나 감시되지 않음; 옛 상태 폴더를 옮기지 않거나, 새 폴더 위로 옮기거나, 옛 폴더의 아카이브나 기록을 더는 읽지 않거나, 보호하지 않음; 자동 압축을 판단하지 않음; 접기 전 정리 턴을 Stop 게이트가 붙잡음(양쪽 경로 모두); 접기 판단의 발췌를 보내지 않거나, 가리지 않거나, 자르지 않음; 도구 입력을 접지 않음; 요약된 대화를 보관하지 않음; `/compact` 지시를 넘기지 않거나 플러그인의 요청 뒤에 둠; 재압축 카운터를 초기화하지 않거나 보고 줄이 빠짐; Stop 게이트 강등이 적용되지 않거나, precision 기준이나 라벨 수를 무시하거나, `/jev-mark`가 점검하지 않음; 보고에서 지연 시간이 빠지거나 2초 timeout이 바뀜; Jev의 지시 판독을 `active`에서 적용하지 않거나, `shadow`에서 적용하거나, 규칙의 결정에까지 적용함; `read_coordinate`가 마지막 요청이나 줄 범위를 무시함. 처음 심었을 때 살아남은 결함이 둘 있었다. 규칙의 결정에까지 적용하는 결함은 테스트가 제목 대신(빠진 줄이 제목을 다시 적는다) Orca 규칙의 본문을 확인하도록 고친 뒤 실패했고, `shadow`에서 적용하는 결함은 두 번째 조건이 가리고 있어 두 조건을 함께 없애도록 다시 심은 뒤 실패했다. 그 전에는 테스트가 254개였고, 브라우저 라우팅과 블록 판단 작업이 남긴 것보다 79개 많았다. 그 작업에 대해서는 아래 결함을 하나씩 심어 보았고, 매번 테스트가 하나 이상 실패했다: PII 이식본을 바꿈(입력 2,614건을 비교하는 parity 테스트 하나); 접힌 메시지의 이미지를 버림, 문서를 이미지와 다르게 처리함; dry-run이나 접기 판단이 api 보기를 읽지 않음; 가리기 전에 자름(도구 게이트, 브라우저 라우팅, 접기 판단의 요청과 호출 줄, 블록 유지 요청, Stop 게이트의 문단); 조직 파일을 자르거나 대체함; 접기가 접지 않을 결과까지 판정함; 요약이 대체하는 구간에 사용자 프롬프트를 남김; 상황판이 오래됐는데 요약을 실행함; 요약 뒤에 접힌 포인터를 되돌리지 않음; 자동 접기가 기다리기 시작한 시각을 기록하지 않음; 압축을 기록하지 않거나 트리거를 잘못 기록함; 요약 중 표시를 하지 않음; 노트에서 Handoff 안내를 빼거나 상황판에 Handoff 절이 있다고 봄; 3시간 제안이 동의로 넘어가지 않음; 제안의 답을 무조건 동의로 읽음; 압축 보고를 빈 것으로 보여 줌; 작은 이미지도 축소함; 빠뜨린 줄 범위를 알리지 않음; 공유 설정을 무시함; `/conjev:onboard`가 키 출처를 숨기거나, 다시 실행해도 키를 새로 찾지 않거나, 세션 중에 놓은 키를 게이트에 넘기지 않거나, 플러그인 접두어가 붙은 자기 이름을 알아보지 못하거나, 특정 사용자의 키 파일 경로를 적음; 그리고 `active`인 접기 관련성이 하한선을 무시하거나, 접기를 정하지 않거나, 자동 압축에서도 물어봄. 배선 하나만 실패하는 테스트가 없다. 접기 타이머가 하는 유휴 판정을 지워도 통과한다([한계](#한계) 참고). 지시 필터에 대해 심은 결함은 다음과 같다: 결함 19개를 하나씩 다시 심어 보았고, 매번 테스트가 하나 이상 실패했다. 지시 필터에 대해 심은 결함은 다음과 같다: 항상 유지 목록을 무시함, 미룬 chunk를 다른 chunk의 내용을 이미 말하는 것으로 셈, 사용자 규칙 때문에 프로젝트 규칙을 뺌, 늦게 온 Jev 답을 버림, 첨부 fragment 개수 계산이 읽을 수 없는 chunk 이름, 메모리나 조직 파일을 자름, 코드 펜스 안의 제목을 절로 인식함, 설정이 꺼져 있는데 기록을 씀. 0.0.1부터 있던 결함은 다음과 같다: 폴더 전체를 대상으로 한 정리, 판단에 고정된 크기 하한을 씀, 예전 방식의 턴 계산, 읽을 수 있는 상태로 남은 폴더, 실패한 `chmod`를 무시함, 아카이브를 직접 읽을 수 있음, `HOME` 없이 실행한 `/compact`, 대화를 보지 않고 센 fragment 개수, 기억하지 못한 대기 중 프롬프트, 접기 뒤의 실패가 접기를 되돌림, 인용된 여는 태그를 블록으로 인식함.

</details>

연구 도구는 `CONTEXT_HARNESS_STATE_HOME`에 절대 경로를 지정해 아카이브·판정 기록·정리를 그 경로의 `.conjev/state/`로 분리할 수 있다. 지정 시 개인·이전 상태 폴더의 이관과 대체 읽기는 하지 않는다. 기본 상태 경로와 이관 동작은 그대로다. 이 설정은 자격 증명·공유 설정·파일 접근 권한의 격리를 제공하지 않는다.

## 출처

판단 계층은 *Jev Engineering for Coding Agents*([PDF](https://drive.google.com/file/d/17h982xvsL3E7b80iGmOCfKp9qTOW9ohv/view))의 역할 분담을 따른다. 이 문서는 Diogo Almeida(TypeSafe)의 설계 노트를 바탕으로 2026년 9월에 독립적으로 엮은 작업 노트이며, TypeSafe와 관련이 없고 TypeSafe의 승인도 받지 않았다. 역할 분담은 이렇다: 모델은 글을 쓰고, Jev는 판단하며, 코드는 선택지를 만들고 그 답에 따라 실행한다. 완료된 도구 출력을 요약하지 않고 주소가 붙은 한 줄 포인터로 접는다는 아이디어는 황대진과 Yeni의 *The Context Coordinate System and the Principle of Unbroken Memory*(Philosophy That Works, 2026; DOI [10.5281/zenodo.23377916](https://doi.org/10.5281/zenodo.23377916); [저장소](https://github.com/philosophythatworks/context-lattice))에서 왔다. 이 플러그인은 독립적으로 구현했으며 그 프로젝트의 코드를 포함하지 않는다. 블록 나누기와 2단계 관련성 판단(`hooks/blocks.ts`, `hooks/relevance.ts`)은 Deukwoong Woo, a2sys의 [jevfetch](https://github.com/a2sys-ai/jevfetch)(MIT, 커밋 167fe8f)에서 옮겨 왔다. 한국어 개인정보 단계(`hooks/pii/`)는 [maskingtape](https://github.com/ChoHyeonChan/maskingtape) main 커밋 2802949(Apache-2.0)을 TypeScript로 옮긴 것이며, 라이선스와 NOTICE는 `hooks/pii/LICENSE`와 `hooks/pii/NOTICE`에 있고 옮긴 파일마다 머리에 그 사실을 적었다. 관련 연구로는 [Lindenbauer et al., 2025](https://arxiv.org/abs/2508.21433)의 observation masking과 Anthropic의 [context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing)이 있다.

## 버전

플러그인이 초기 단계인 동안 버전은 0.0.x에 머문다. 0.0.1은 context-fold 0.0.2와 jev-harness 0.0.3을 합친 첫 릴리스다. 0.0.2는 지시 필터를 추가했다. 0.0.3은 표시할 내용이 생기기 전까지 상태 줄을 비워 둔다. 아직 릴리스하지 않은 것: 기본으로 꺼진 접기(`fold`)와 모델 턴으로 세는 최근 턴, 웹 읽기, 접힌 결과의 블록 유지, 브라우저 라우팅, 민감 정보 제거의 한국어 개인정보, 최근 구간만 남기는 요약과 그 뒤의 프롬프트·포인터 복원, 자동 접기의 양보, 상황판의 핸드오프 절과 생성 제안, `imageMaxPx`, `query`를 받는 `read_coordinate`, 공유 설정 폴더와 `/conjev:onboard`, `active`인 접기 관련성, 동의를 받아 켜지는 `auto` Jev 게이트와 `jev` 스위치와 첫 실행 설정 안내, `~/.conjev/state` 아래의 상태, 접힌 도구 입력과 요약된 대화의 보관, 라벨에 따른 Stop 게이트 강등, `active`에서 적용하는 Jev의 지시 판독.

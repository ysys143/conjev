Q1의 V/H 비교는 V의 캡처 문제로 결측이다. H의 10/12 완료와 도달 범위의 위반 0건은 확인했지만, 이를 V보다 낫거나 나쁘다는 결론으로 확장하지 않는다.

Q3의 S1/S0 비교도 S1의 캡처 문제로 결측이다. S1에서 관측한 Stop 후보는 9건, 직접 Jev 판정 3건, 조건부 문구 스킵 6건, 실제 차단 0건이다. 교정 후 추가 진척을 측정할 차단 사례는 없었다. 자연스러운 조기 반환 기회 전체의 정답 여부와 active/off 완주 차이는 확정할 수 없다. 통제 문구의 장치 통과를 이 완주 효과의 증거로 쓰지 않았다.

유효한 H·S0 자료의 세 압축 경계는 모두 결과 2개·합계 4,000자 최소치를 충족했다. 실제 도달한 압축 후 후속 단계 5곳에서는 `INTENT.md` → `PHASE.md`를 먼저 읽고 두 도구 결과가 돌아온 뒤 첫 Write/Edit/Bash를 시작했다. 후속 단계 자체에 미도달한 압축은 준수 실패로 세지 않았다.

과거 출력의 값을 직접 쓰는 H의 8·10단계와 S0의 8단계에서는 6개 값 모두 정답이었고, 값을 처음 명시적으로 쓰기 전 `read_coordinate` 조회와 작업 파일 읽기가 관측됐다. 6개 값은 단계 시작 요청 문맥에도 이미 들어 있었다. 따라서 어떤 입력을 내부적으로 채택했는지, 아카이브 조회가 기억 실패를 해결했는지는 확인할 수 없다. [복구 경로 관측](../../experiments/long-task/runs/pilot-20261026-2/recovery-observations.json)에 값별 근거를 남겼다. 미도달 통합 단계의 경로는 관측했다고 쓰지 않았다. 네 조건 모두 고정된 확인 응답을 사용하는 추가 질문 이벤트는 0건이었다.

## 실패와 제외 범위

1. **최초 V 시도: 평가기 후처리 결함.** 12단계와 재진술 뒤 도구 호출 집계가 실패했다. 101개 호출 중 9개는 작업 폴더를 붙인 Bash 표현, 39개는 `Edit.replace_all=false` 생략 차이였다. 그때 실제 종료 코드가 파일로 보존되지 않아 정식 비교에서 제외했다. 버전 2는 두 표현만 엄격하게 대조하고 실제 종료 기록을 후처리보다 먼저 쓴다. 잘못된 외부 경로나 편집 값 변화를 받아들이는 변이는 거부했다. 해당 V의 CPU 12단계 통과와 제외 표본 Stop 13건·재진술 7개 판정은 별도 보존했으며 정식 비교에 사용하지 않았다.
2. **대체 V: 상류 응답 미수신 1건.** 79개 요청 기록과 시작 기록은 모두 남았지만, `8e50fb8744c3451dbacaf5256c5c7da6` 요청은 `BrokenPipeError`, 응답 0바이트, 상류 상태·사용량 미확정이다. 로컬 프록시의 502 뒤 CLI가 동일 본문을 재시도해 200을 받았다. 실제 Claude 종료 코드는 0이지만 원요청의 응답·사용량은 복구되지 않았다.
3. **S1: 입력 상한과 상류 응답 미수신이 함께 발생.** 69개 요청 중 `fcc3e808858344ce8f11054660bc3039`가 같은 유형의 0바이트 오류였고 후속 동일 본문 요청은 성공했다. 상한 도달 자체는 유지하지만, 캡처 완전성을 충족하지 못한 실행을 유효한 비교 자료로 바꾸지 않았다.

두 연결 실패의 근본 원인은 이번 증거로 확인할 수 없다. 원래 불완전 기록과 `evidence_complete=false`를 고치지 않았다. 실패한 원요청 사용량은 0으로 계산하지 않는다.

당시 Codex는 첫 V의 대체를 계획서의 1쌍 제한 소진으로 해석하고 추가 실행을 멈췄다. 이 제한을 사용자가 정한 승인 한도처럼 설명한 것은 잘못이었다. 사용자는 재시도 횟수를 지정하지 않았으며, 2026-10-27에 파일럿을 고쳐 제대로 실행할 때까지 계속하라고 지시했다. 이전 실패 증거는 그대로 보존하고, 새 실행·수집 사양으로 네 조건과 두 비교쌍을 다시 실행한다. 이 문서의 기존 수치는 이전 사양의 관측이며 새 결과와 합치지 않는다.

완전한 종료·수집 경로를 12단계 파일럿 이전에 충분히 실행하지 못해 최초 V의 시간을 소모했고, 실제 부하에서는 짧은 준비 검사에서 드러나지 않은 연결 실패와 입력 상한이 발생했다. 선행 테스트 통과 수는 이 실제 파일럿의 성공을 보장하지 않았다.

## 증거와 실행 명령

모든 `runs/` 표기는 `experiments/long-task/` 아래다. 현재 작업 자료는 다음과 같다.

- [실행·집계 데이터](../../experiments/long-task/runs/pilot-20261026-2/report-data.json), [첫 V 실패 감사](../../experiments/long-task/runs/pilot-20261026-1/failure-audit.json), [대체 V 캡처 감사](../../experiments/long-task/runs/pilot-20261026-2/capture-failure-audit.json), [S1 캡처 감사](../../experiments/long-task/runs/pilot-20261026-2/S1-capture-failure-audit.json)
- `/private/tmp/ch-research-pilot-20261026-2/`: 원래 네 조건, 실행 사양, 스냅샷, 요청, 종료 기록, 부분 채점, 판정 패킷
- [보존 증거 묶음](../../experiments/long-task/runs/pilot-20261026-2/evidence-packet/): 원본의 저장소 내 복사본. 모델에 전달하는 작업 폴더 밖에 보관하며, 별도 해시 목록으로 원본과 대조한다.

대표 실행 명령은 다음과 같다. 실제 전체 인자와 종료 코드는 각각의 네이티브 `job.launcher.py`·`job.json`에 남았다.

```text
python3 experiments/long-task/native_run.py --script experiments/long-task/pilot_run.py --cwd /Users/jaesolshin/Documents/GitHub/context-harness --receipt experiments/long-task/runs/pilot-20261026-2/job.json -- --config /Users/jaesolshin/.claude-reserach --root /private/tmp/ch-research-pilot-20261026-2 --ledger /Users/jaesolshin/Documents/GitHub/context-harness/experiments/long-task/runs/study-spend.sqlite3 --admission /private/tmp/ch-research-phase1-20261026-19/acceptance.json
python3 experiments/long-task/native_run.py --script experiments/long-task/runs/pilot-20261026-2/continue-planned-arms.py --cwd /Users/jaesolshin/Documents/GitHub/context-harness --receipt experiments/long-task/runs/pilot-20261026-2/continuation-job.json
python3 experiments/long-task/runs/pilot-20261026-2/assess-ceiling.py --arm H
python3 experiments/long-task/runs/pilot-20261026-2/assess-ceiling.py --arm S0
python3 experiments/long-task/native_run.py --script experiments/long-task/runs/pilot-20261026-2/grade-available.py --cwd /Users/jaesolshin/Documents/GitHub/context-harness --receipt experiments/long-task/runs/pilot-20261026-2/available-grading-job.json
```

원래 파일럿 작업은 엄격한 캡처 검사에서 exit 1이었다. 남은 세 조건의 시도를 기록한 실행은 exit 0, 부분 판정 실행도 exit 0이었다. 이 두 실행기 종료 코드가 파일럿의 완료 기준 통과를 뜻하지는 않는다.
